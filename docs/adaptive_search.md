# 历史信息如何指导新版变量选择

本修订于 2026 年 10 月 10 日完成，对应包版本 0.4.0。固定支持集上的优化目标不变；变化是怎样选择下一次需要完整求解的支持集，以及怎样复用已经得到的解。英文和中文理论报告给出同一套推导，附录 C 证明定量保证。

## 1. 一次求解留下两种可复用的信息

完整求解 `GateOracle.solve(z)` 返回一个原问题可行检验和一个修复后的对偶证书。原始检验保存每个目标位置的两类损失 `test.pool_losses`，以及类别价格 `test.multipliers`。它们都是从可行评分得到的量，没有对新组合的风险作统计猜测。

在新组合上固定这些损失和价格，只重算源点额度：

\[
a_i^s(z)=\max_\ell\{\Phi(y_i u_\ell^s)-\lambda_{c_i}^s\mathbf d_{i\ell}^{\top}z\}.
\]

每一个原有限问题的不等式立即成立。因此 `GateOracle.reprice(test,z)` 返回一个真的可行检验，以及它的风险上界。程序在最大值上加微小向上修复量，并与真实的常数检验比较；不能只把一个数字截断到 B 而继续返回另一个风险更高的检验。

旧对偶证书则给出整个选择域上的分式下界。`SearchHistory.densify` 在候选点处重新计算这个已有分式的切线；它不求新的运输矩阵，也不调用连续优化器。这比只保留旧参考点上的一条切线多用了已有证书的信息。

## 2. 哪些组合值得完整求解

`SearchHistory.lower(z)` 是所有已保留割的最大值。默认算法的全局主问题使用同一组割。`SearchHistory.upper(z)` 是历史评分在 z 上重算后最好的可行上界，并缓存所对应的真实检验。

候选的区间宽度是

\[
W_t(z)=U_t(z)-m_t(z).
\]

`proposal_pool` 包括当前最好支持的坐标交换、近期割的价格排序、上次全局候选和受限数量的随机多样性候选。候选数有固定上限；它们只需要便宜的历史界计算，不全部调用完整 oracle。

`adaptive.solve_adaptive` 用

\[
A(z)=(UB-m(z))_+W(z)
\]

给候选排序。第一个因子表示这个组合仍可能改善当前结果；第二个因子表示它尚未被历史信息充分确定。这个量只负责排序，绝不能被当作全局下界。

候选必须同时满足 `m(z)<UB` 和 `W(z)>alpha*(UB-LB)`，才进行完整求解。默认 alpha=0.5。区间已经很窄的组合，即使预测看起来不错，也不会消耗一次完整评估。

## 3. 全局主问题怎样保障进展

默认每三个搜索轮次做一次全局认证；若启发式候选都不符合信息条件，则立即做认证。旧的全局下界在这期间仍然有效，因为割只增加。

主问题返回全局下界和整数候选。先在候选上转移历史检验并更新 UB，再决定是否需要完整求解。若主问题候选与下界之差为 xi，则该候选的区间宽度至少为 `UB-LB-xi`。这正是附录 C 的保底论证。

未解决的主问题原始目标不是全局下界。整数主问题采用有效的 `mip_dual_bound`；连续根节点 LP 只有成功达到全局最优时才用 `fun` 更新 LB。失败结果不贡献证书。

## 4. 定量保证与代码中的量

从数据计算

\[
M_j=\max_k\frac{\sum_{i\in I_k}q_i\max_\ell d_{i\ell,j}}{\theta_k},
\qquad \rho(z,z')=\sum_jM_j|z_j-z'_j|.
\]

`history.metric_weights` 就是 M。归一化对偶修复保留 `mu <= tau*M`，对应正文中的 `mu_normalized <= M`。这个限制不会删去需要的证书。

若每次完整评估保留的可行上界与某条割在该点的差至多 delta，则

\[
W(z)\le\delta+B\min_s\rho(z,z^s).
\]

原因是：移除坐标才能增大历史上界，添加坐标才能降低旧割；两部分分别占据相反的坐标变化方向，所以总系数是 B。

程序先完整求解，再检验实际历史间隙是否不超过 `anchor_target=alpha*tolerance/2`。若有必要，复用模型并收紧求解精度，最多追加 `max_refinements` 次。若仍达不到所需精度，返回 `oracle_accuracy_limit`；不能因为求解器自称成功而直接满足定理假设。

信息筛选使得在全局差值仍大于 epsilon 时，完整评估的组合两两相隔大于 `(alpha*epsilon-delta)/B`。因此调用次数受该距离下能容纳的不同组合数量控制。理论还将它转为可直接由 M 的尾和计算的界。没有额外结构时，这个界仍可能很大。

定理计算的是达到指定精度的二元评估次数。输出中的 `oracle_calls` 还包括连续根节点和精度重试；`accurate_support_evaluations`、`refinements` 单独记录，不能混为一个数量。定理不保证每次 MILP 或连续子问题的运行时间。

## 5. 真正的热启动保存了什么

Logistic 的风险模型保留同一个参数化 CVXPY 问题，改变 z 参数后继续求解。原始问题、连续延伸原始问题和对偶问题分别保存模型，避免混用不同变量结构。变量数值和可复用的 Clarabel 工作区用于后续求解；测试核对了实际对象复用。

半合页使用 SciPy/HiGHS LP，不传无效的 x0 参数来声称热启动。它仍通过对偶分式、可行评分、候选界缓存来复用已经得到的数学信息。代码没有将旧运输矩阵固定为新 oracle 的可行域。

## 6. 读代码的顺序

| 文件 | 先看哪个部分 | 要检查的数学关系 |
|---|---|---|
| `oracle.py` | `reprice`、`_repair_dual` | 转移检验可行；修正向量几何界和对偶修复 |
| `history.py` | `add`、`upper`、`lower`、`densify` | 历史两侧界和额外切线；候选上界必须附真实检验 |
| `adaptive.py` | `evaluate`、`master`、主循环 | 实际精度检查、LB 来源、信息阈值与全局保底 |
| `solver.py` | `solve` | 默认新算法与保留的 `search='master'` 基线 |
| `test_adaptive_search.py` | 全部测试 | 独立枚举、几何宽度界、保底候选与排序不充当证书 |

旧的冻结实验方法 `risk`、`risk_no_root`、`box`、`triangle` 保留原主问题搜索路径。新方法使用 `risk_adaptive`，新增验证保存在单独的 20261010 目录。历史报告的 1,640 条结果没有重新标成新版结果。
